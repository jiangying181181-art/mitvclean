# 从真机反查广告域名：两条腿走路

这是本项目最值得记录的方法论。**只做静态分析一定会漏**，这是实测踩出来的。

---

## 问题：为什么"禁包"解决不了贴片广告

小米电视的贴片广告（播放电影前那段 30/36/120 秒不等的视频）有三个特点：

1. **不是独立包** —— 它在 `com.mitv.tvhome` 这个桌面包里，由一个 Activity 承载
2. **不能组件级禁用** —— 部分固件禁止 `pm disable` 改组件状态：
   ```
   $ adb shell pm disable --user 0 com.mitv.tvhome/.PreDetailsActivity
   SecurityException: Shell cannot change component state for
     com.mitv.tvhome/com.mitv.tvhome.PreDetailsActivity to 2
   ```
   禁整包又会把桌面一起干掉，电视进不去系统
3. **地址是服务端给的** —— APK 里只有配置**键名**，没有值

第 3 点是关键。扒 APK 能看到：

```
com.mitv.tvhome.ads.filmad.FilmAdBean
com.mitv.tvhome.util.InternalFrontAdCtlManager   →  fetchMiFrontAdConfig
com.mitv.oneplayer.ad.FrontAdView
close_after_ad_video_interval_cnt                ← 广告时长计数器
close_front_ad_video_interval_cnt
film_ad_online_server                              ← 只有键名，值在服务端
film_ad_review_server
```

`film_ad_online_server` 的**值**在服务端配置里。静态扫 APK 拿不到它。

## 两条腿

### 腿一：静态 —— 扒 APK

只能拿到 `/data/app` 下的（用户安装的应用）；`/system/app` 下的系统应用 shell 读不到 base.apk。

```bash
adb shell cp /data/app/com.mitv.tvhome-XXXX/base.apk /data/local/tmp/
adb pull /data/local/tmp/com.mitv.tvhome-XXXX.apk .
```

然后用 zipfile 逐条目扫（**`strings` 对压缩的 APK 无效**，必须解开）：

```python
import zipfile, re
DOMAIN_RE = re.compile(
    rb"[a-z0-9][a-z0-9-]{1,40}(?:\.[a-z0-9-]{1,30}){1,5}"
    rb"\.(?:xiaomi|com|cn|net|tv|org|io|me)"
    rb"\.(?:com|cn|net|tv|org|io|me)"
)
z = zipfile.ZipFile("com.mitv.tvhome.apk")
for name in z.namelist():
    if not name.endswith((".dex", ".arsc", ".xml", ".so")):
        continue
    for m in DOMAIN_RE.findall(z.read(name)):
        ...
```

拿到的多半是硬编码域（`api.account.xiaomi.com`、`appstore.mitv.xiaomi.com`…），
**广告通道反而在里面**。

### 腿二：动态 —— 抓 logcat

服务端下发的地址，只有在运行时日志里：

```bash
adb shell logcat -d -v time > logcat.txt
```

小米桌面的配置请求打的是 `PWHttp` 这个 tag，里面是完整 JSON：

```
D/PWHttp: {"status":0,"ver":...,"data":{...,"enable_new_boot_ad":false,
  "client_arch_network_optimise":{"host_merge":["appstore.v.mitvos.com",
  "om.v.mitvos.com","videodaily.ptmi.gitv.tv"]}, ...}}
```

> 电视的 logcat 中文是 GBK 编码，在 Windows 终端里直接看会乱码。
> 建议拉到电脑后用 Python 按 UTF-8 读（`adb shell logcat -d` 走的是 shell 管道，
> 编码会在传输中被破坏；更稳的是 `adb exec-out logcat -d -v time > file`）。

正则提域名：

```python
re.compile(r"[a-z0-9][a-z0-9.-]{2,60}"
           r"\.(?:xiaomi|com|cn|net|tv|org|io|me|mitvos|gitv)"
           r"\.(?:com|cn|net|tv|org|io|me)")
```

## 实测对比

某台小米电视（MiTV-ANSP0 / Android 9 / 固件 22.12.6.2963）：

| 来源 | 域名数 | 关键收获 |
|---|---|---|
| 静态（3 个 APK）| 71 | `adx.v.mitvos.com`（广告交易平台）、`sdkconfig.ad.intl/rus/india.xiaomi.com` |
| 动态（logcat）| 19 | **`cp-ppvideo.cdn.ptmi.gitv.tv` 等 4 个 `cp-` 前缀的 CDN** |

那 4 个 `cp-*.cdn.ptmi.gitv.tv` **只在 logcat 里出现过**，静态扫 APK 找不到。
而它们恰好就是贴片广告素材的存放位置。

## 怎么判断"这个域是广告域"

本项目 `mitvclean/ads.py` 里的启发式（按优先级）：

```python
AD_HINTS = (
    # 小米广告配置与交易平台
    "ad.xiaomi", "ad1.xiaomi", "ad.mi.com", "sdkconfig.ad", "sdkconfig.xiaomi",
    "track.ad", "monitor-check.ad", "adx.v.mitvos", "ad.hpplay", "adeng.hpplay",
    # 各视频内容方的广告通道
    "cupid", "ptqy", "mgtv.com", "cibntv", "atiane", "aiseet", "aiseejapp",
    "gvod.", "mobaliyun", "cp-", "filmtv",
)

SOURCE_HINTS = (
    "pandora", "mitvos", "ptmi.gitv", "ptxl.gitv", "migc", "migutv",
    "enttv", "bestv", "kuyun", "icntv", "market.xiaomi", "mddmcn", "gitv.tv",
)
```

**但启发式只是初筛，最终以"拦了之后广告还在不在"为准。**

所以正确的工作流是：

```
scan（两条腿取并集） → 生成 hosts → 配到路由器 → 重启电视 → 试播
  → 广告还在？→ 重跑 scan，看 logcat 里有没有新域名（说明它换了地址）
  → 视频打不开？→ 删掉对应那行
```

这是一个**需要迭代**的过程，不是一次性的黑名单。

## 时长不等的广告说明了什么

实测用户反馈贴片广告有 30 秒 / 36 秒 / 121 秒三种时长。

**不是随机广告，是每条内容源各下发一条。** 电影 A 的片头广告是 30 秒（本地广告主的短广告），
电影 B 的是 121 秒（品牌广告）。

所以：

- 拦一个源不够，**要多源同拦**
- 源越多，误伤正片的概率越高 → 所以清单要分层（第 1 组安全，第 2 组可能打不开内容）
- 内容源会变 → **清单需要定期更新**，不能一劳永逸
